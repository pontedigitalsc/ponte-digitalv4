# Guia da Empresa que Aprende

**Programa:** 26 — Ativação Cognitiva da Empresa Zero
**Propósito:** Transformar erros em patrimônio. Evitar repetir erros.
**Data:** 26/07/2026
**Versão:** 1.0

---

## O que é uma empresa que aprende

Uma empresa que aprende não é aquela que não comete erros. É aquela que:

- Registra todo erro como ativo de conhecimento
- Extrai aprendizado de cada falha
- Nunca repete o mesmo erro duas vezes
- Celebra a descoberta, não a perfeição
- Acumula patrimônio intelectual a cada cicatrização

Erro não registrado é erro que será repetido. Erro registrado e analisado é investimento com retorno garantido.

---

## O ciclo do erro produtivo

```
ERRO → REGISTRO → ANÁLISE → HIPÓTESE → EXPERIMENTO → APRENDIZADO
  ↑                                                           │
  └─────────────────────── NOVO CICLO ────────────────────────┘
```

### 1. ERRO
Algo aconteceu diferente do esperado. Uma decisão deu resultado negativo. Um processo falhou. Um cliente não respondeu como previsto.

### 2. REGISTRO
O erro é documentado imediatamente, sem julgamento. Apenas os fatos: o que aconteceu, quando, onde, em que contexto.

### 3. ANÁLISE
Perguntas a responder:
- Qual era a expectativa?
- O que realmente aconteceu?
- Qual a diferença entre os dois?
- O que isso revela sobre nosso entendimento do negócio?

### 4. HIPÓTESE
O erro gerou uma pergunta. Essa pergunta vira hipótese: "Se fizermos X diferente, o resultado será Y?"

### 5. EXPERIMENTO
A hipótese é testada. Pequeno, rápido, barato. O suficiente para gerar evidência.

### 6. APRENDIZADO
O experimento confirma ou refuta a hipótese. De qualquer forma, aprendemos. O aprendizado é registrado como conhecimento confirmado.

## Como NÃO tratar erros

| Comportamento | Consequência |
|---------------|-------------|
| **Esconder** | O erro não vira aprendizado. Alguém vai repeti-lo. |
| **Ignorar** | O padrão não é identificado. O erro volta em outro contexto. |
| **Punir** | As pessoas param de registrar. Os erros ficam invisíveis. |
| **Repetir** | O mesmo erro acontece de novo. Perde-se tempo, dinheiro e credibilidade. |
| **Justificar** | "Foi porque..." em vez de "O que podemos aprender?". A defesa impede a descoberta. |
| **Minimizar** | "Não foi nada". Toda falha carrega informação valiosa. |

## Como tratar erros

### 1. Celebrar o registro
O momento em que um erro é registrado é um momento de vitória. Algo foi descoberto que antes estava oculto. Agora podemos agir.

**Frase oficial:** "Ótimo. Descobrimos algo que não sabíamos."

### 2. Analisar sem julgamento
A análise do erro não busca culpados. Busca causas. A pergunta não é "quem fez", mas "o que no nosso processo permitiu isso acontecer?".

### 3. Extrair aprendizado
Todo erro responde a pelo menos uma destas perguntas:
- O que nosso modelo de negócio não previa?
- O que nosso entendimento do cliente não capturava?
- O que nosso processo não cobria?
- O que nossa hipótese não considerava?

### 4. Documentar como ativo
O erro registrado vira um ativo intelectual. Pertence à empresa, não à pessoa. Fica acessível para consulta futura.

## Biblioteca de Erros

Modelo para catalogar erros como ativos de conhecimento.

```
ID: ERRO-{NUMERO_SEQUENCIAL}
DATA: YYYY-MM-DD
TÍTULO: nome curto que identifica o erro
GRAVIDADE: [leve | moderado | grave | crítico]
CATEGORIA: [comercial | operação | produto | técnico | decisão | comportamento]
```

### Template de registro de erro

```
## O QUE ACONTECEU
[Descrição factual. Apenas os fatos. Sem opinião, sem julgamento.]

## POR QUE ACONTECEU
[Análise de causas. O que no processo, modelo, entendimento ou execução permitiu.]

## O QUE APRENDEMOS
[Conhecimento extraído. O que agora sabemos que não sabíamos antes.]

## O QUE FAREMOS DIFERENTE
[Ação concreta. O que vai mudar na operação, produto ou processo.]
```

### Exemplo preenchido

```
ID: ERRO-001
DATA: 26/07/2026
GRAVIDADE: moderado
CATEGORIA: comercial

## O QUE ACONTECEU
Lead qualificado como QUENTE não respondeu a 3 tentativas de contato. Perdemos o lead após 2 semanas de acompanhamento.

## POR QUE ACONTECEU
A temperatura do lead foi definida com base em critérios subjetivos (o lead "parecia interessado"). Não havia critério objetivo de qualificação.

## O QUE APRENDEMOS
Temperatura do lead precisa de critérios objetivos vinculados a ações concretas (respondeu diagnóstico, agendou reunião, abriu proposta). Interesse percebido não é interesse real.

## O QUE FAREMOS DIFERENTE
Criar critérios de temperatura: QUENTE = respondeu diagnóstico + agendou reunião. MORNO = respondeu diagnóstico. FRIO = apenas cadastrou.
```

## Rituais de Aprendizado

### Revisão Semanal de Erros

| Elemento | Descrição |
|----------|-----------|
| Quando | Toda sexta, 30min |
| Quem | Fundador + Arquiteto de Conhecimento |
| O que faz | Revisa erros da semana, classifica, extrai aprendizado |
| Pauta | 1. Erros novos registrados. 2. Padrões identificados. 3. Aprendizados extraídos. 4. Ações definidas. |

### Sexta do Aprendizado

| Elemento | Descrição |
|----------|-----------|
| Quando | Última sexta do mês, 1h |
| Quem | Toda a empresa (hoje: fundador + IA) |
| O que faz | Revisão ampla do mês: o que aprendemos, o que mudamos, o que ainda não entendemos |
| Formato | Leitura do Diário Cognitivo do mês, revisão de hipóteses, atualização do conhecimento confirmado |

## Como transformar um erro em RFC

Nem todo erro vira RFC. Apenas erros que indicam necessidade de mudança estrutural.

### Critérios para RFC a partir de erro

1. O erro se repetiu mais de uma vez (padrão)
2. O erro revelou uma falha no processo, não na execução
3. A correção exige mudança documentada e aprovada

### Fluxo

```
Erro registrado (Camada 1)
    ↓
Padrão identificado (Camada 2)
    ↓
Hipótese de correção (Camada 3)
    ↓
Conhecimento extraído (Camada 4)
    ↓
RFC proposta (Camada 5)
    ↓
Implementação
    ↓
Impacto registrado no Diário (Camada 1)
```

## Como a IA deve ajudar

### Detectar padrões de erro recorrentes
A IA varre o Diário Operacional e o Catálogo de Observações para identificar erros que se repetem. Se o mesmo tipo de erro aparece 3+ vezes, a IA sugere uma hipótese de correção.

### Sugerir correções
Baseada no Conhecimento Confirmado, a IA propõe ações corretivas para erros identificados. "Erros semelhantes a este foram corrigidos com a seguinte abordagem..."

### Não repetir
Antes de qualquer recomendação, a IA consulta a Biblioteca de Erros. Se a recomendação já foi tentada e falhou, a IA não repete — sugere alternativa ou pergunta se o contexto mudou.

### Gerar alertas preventivos
Se a IA identifica condições semelhantes a erros passados, emite alerta: "A situação atual se parece com o erro ERRO-003. Deseja revisar antes de prosseguir?"

## Exemplos de erros que viram patrimônio

### Erro → Novo processo
**Erro:** Lead quente perdido por falta de acompanhamento.
**Aprendizado:** Temperatura precisa de critérios objetivos.
**Patrimônio:** Sistema de qualificação de leads com critérios vinculados a ações.

### Erro → Novo insight de produto
**Erro:** Diagnóstico levou 12 minutos, não 5.
**Aprendizado:** O empresário não tem 12 minutos contínuos para responder perguntas.
**Patrimônio:** Diagnóstico assíncrono dividido em blocos de 2 minutos.

### Erro → Nova hipótese de negócio
**Erro:** Cliente não retornou após primeira sessão.
**Aprendizado:** O valor percebido não foi suficiente para motivar retorno.
**Patrimônio:** Hipótese H-013 (compartilhar dados após ver valor) foi reforçada.

### Erro → Nova regra operacional
**Erro:** Duas tarefas criadas com o mesmo título e descrições diferentes.
**Aprendizado:** Time precisa de convenção de nomenclatura.
**Patrimônio:** Guia de nomenclatura de tarefas na Empresa Zero.

## Mapa da maturidade: como a empresa aprende

| Estágio | Como trata erros | Estado |
|---------|------------------|--------|
| 1. Negação | Erros são escondidos ou ignorados | Reativo |
| 2. Reação | Erros são corrigidos, mas não registrados | Corretivo |
| 3. Registro | Erros são registrados, mas não analisados | Documental |
| 4. Análise | Erros são analisados e geram aprendizado | Analítico |
| 5. Prevenção | Erros são previstos e evitados | Preditivo |
| 6. Cultura | Erros são celebrados como fonte de conhecimento | Sistêmico |

**Onde a Empresa Zero está hoje:** Estágio 2 (Reação). Erros são corrigidos, mas nem sempre registrados.
**Meta P26:** Atingir Estágio 4 (Análise). Todo erro registrado e analisado. Aprendizado extraído em 100% dos erros moderados+.
